# AI 小说工坊

系统化生成长篇网文的本地网站：**一句灵感 → 世界观 → 人物 → 总纲 → 章节大纲 → 正文**，每一步都能看、能改、能重新生成；写完的章节自动沉淀为“记忆”（摘要 / 人物状态 / 伏笔 / 前情提要），保证写到几百章也前后一致。

- 任意 **OpenAI 兼容接口**：DeepSeek、通义千问、Kimi、OpenAI、Ollama……
- 唯一运行时依赖是 Zod（校验模型输出），数据是本地 JSON + TXT 文件，方便备份和手动修改
- 生成任务在服务端后台运行，关掉网页也不会中断；网页实时显示生成过程

## 快速开始

需要 Node.js ≥ 20.12。

```bash
cd ai-novel
npm install
copy .env.example .env      # macOS/Linux: cp .env.example .env
# 编辑 .env，填 OPENAI_BASE_URL / OPENAI_API_KEY / MODEL
npm start
```

打开 http://127.0.0.1:3000 → 填写灵感 → 创建作品（默认自动生成设定、人物、总纲和前 10 章大纲）→ 在「概览」或「章节」页点「连续写作」。

## 整体逻辑

### 1. 分层规划（从粗到细）

| 层级 | 内容 | 生成依据 |
|---|---|---|
| 世界观 | 卖点、背景、力量体系、势力、金手指、核心矛盾 | 灵感 + 类型 + 文风 |
| 人物 | 6~10 个核心人物：设定 + **当前状态** | 灵感 + 世界观 |
| 总纲 | 主线概述、分卷（每卷目标/事件/高潮/走向）、结局、长线伏笔 | 世界观 + 人物 |
| 章节大纲 | 每批 10 章：标题、3~5 个情节要点、出场人物 | 总纲 + 前情 + 最近章节 + 未回收伏笔 |
| 正文 | 每章 N 字 | 见下方“写作上下文” |

模型一次只做一层的事，比“一句话直接写全文”稳定得多，而且每一层人都可以介入修改。

### 2. 写作上下文（每章注入什么）

写第 N 章时**不塞前文全文**，而是由上下文编排器（`src/context/`）拼装：

```
写作规范（网文节奏、钩子、去 AI 腔） + 作品信息 + 文风
+ 世界观
+ 全书梗概 → 分段摘要（每 10 章冻结一份） → 近期章节摘要      ← 分层记忆
+ 本章出场人物的设定和【第 N 章开写前的状态】（属性、持有物品、关系、知道的秘密）
+ 相关伏笔：所有主线伏笔 + 近期次要伏笔 + 已超期的伏笔
+ 上一章全文（保证衔接）
+ 本章大纲 + 下一章预告（只用来铺垫结尾）
```

- **有预算**：超出 `CONTEXT_BUDGET` 时，先把世界观、上一章等换成缩略版，再按优先级丢弃可选内容；人物状态、本章大纲等永不裁剪。
- **缓存友好**：稳定的内容在前、变化的在后，同一作品连续写作时能命中接口的前缀缓存。
- **可追溯**：每章实际注入了什么、哪些被裁剪，都存在 `runs/` 里，章节页点「写作上下文」即可查看完整提示词。

### 3. 章后记忆更新（一致性的关键）

每写完一章，用模型把正文“读一遍”，抽取结构化记忆：

- **章节摘要**（150~250 字）
- **状态变化事件**：属性（境界、所在地、伤势……）、物品数量、人物关系、得知的秘密、生死。人物状态**不会被覆盖**，而是「初始状态 + 按章的变化事件」推导出来，因此可以回看任意一章开写前的状态。
- **每条变化必须附正文原句**：程序会在正文里核对，找不到出处的视为编造，直接丢弃。
- **关键变化需要确认**：境界、身份、生死这类变化先进「待办」，确认后才生效；未确认时连续写作会暂停（可在概览关闭）。
- **新登场人物、新秘密**：自动加入人物表 / 秘密表（信息差：人物只能知道自己知道的秘密）。
- **伏笔状态机**：未推进 / 推进中 / 搁置 / 已回收 / 放弃，分主线和次要。主线伏笔每章都会提醒，长期没动静的次要伏笔不再占用上下文。
- **分层摘要**：每写完一段（10 章）生成一份分段摘要并冻结；分段摘要攒够 6 份时，把较早的合并进全书梗概（保留最近 3 份）。早期剧情不会被反复“摘要的摘要”改写失真。

重写、修改某一章时，会先撤销这一章之前产生的全部记忆再重新抽取，不会重复叠加；后续已写的章节会被标记为「待复查」。

### 4. 审校与自动修订

每章写完、更新记忆之前，先过一遍“主编审稿”：

1. **本地规则检测**（不花钱）：统计“不禁、仿佛、嘴角勾起一抹弧度、眼中闪过一丝……”等套话和总结式结尾（规则在 `src/review.ts`，可自行增删）。
2. **模型审校**：对照设定、人物当前状态、最近剧情、上一章结尾和本章大纲，从 8 个维度审稿——设定一致性、人物逻辑、大纲执行、衔接、节奏爽点、章末钩子、AI 腔、对话。每个问题必须**引用原文**，给出严重程度和修改建议，并打 0~100 分。
3. **自动修订**：低于阈值（默认 80 分）或存在严重问题时，按审稿意见**只改有问题的地方**，修订一次。修订稿字数不到原稿一半会被判定为失败、保留原稿。

可在「概览」关闭自动审校或调整阈值；章节页可随时手动「审校本章」「按意见修订」。

### 5. 版本与快照（可以放心试错）

- **章节历史版本**：整章重写、审校修订、按要求修改、手动编辑、恢复版本时，被覆盖的旧正文自动存档（每章保留最近 20 个），在章节页预览或一键恢复。
- **记忆快照**：每写一章前，自动保存人物、状态事件、伏笔和梗概，作为整体回滚的兜底手段。日常修正更推荐在「记忆」页直接删除错误的状态记录或手动修正。
- **旧数据自动迁移**：v0.2 的 `novel.json` 首次打开时自动迁移到新格式，原文件保留为 `novel.v1.backup.json`。

### 6. 一键连续写作

```
循环 N 次：
  有阻塞性待办（待确认的关键变化）？→ 暂停
  找到第一个还没写的章节；没大纲？→ 规划后续 10 章大纲
  记忆快照
  写正文（字数不足 60% 自动续写一次）
  审校 →（不达标）按意见修订一次
  章后记忆回写 → 一段写完时生成分段摘要
```

### 7. 代码结构

| 目录 / 文件 | 作用 |
|---|---|
| `src/prompts/` | **所有提示词模板**，生成质量主要看这里（`shared` 写作规范、`setup` 设定、`plan` 大纲、`write` 正文、`review` 审校、`memory` 记忆） |
| `src/pipeline/` | 流水线：设定、规划、写作、审校修订、记忆回写与分段摘要、连续写作 |
| `src/state/` | 纯函数的记忆逻辑：状态事件推导与撤销、伏笔状态机、抽取结果校验与合并、剧情弧、待办 |
| `src/context/` | 上下文编排：取材（`select`）和按预算裁剪排序（`compiler`） |
| `src/model/` | 数据类型、Zod 校验、旧数据迁移 |
| `src/store/` | 分文件存储（`book/bible/structure/memory/inbox.json`、`chapters/`、`versions/`、`snapshots/`、`runs/`） |
| `src/analysis/` | 本地 AI 腔规则检测（套话表、总结式结尾） |
| `src/routes/` | HTTP API（作品、章节、记忆、任务） |
| `src/jobs.ts` | 后台任务：日志、实时文字、进度、停止、暂停；SSE 订阅 |
| `src/llm.ts` | OpenAI 兼容流式客户端，JSON 提取、校验与重试 |
| `public/` | 前端（原生 JS，hash 路由）：`app.js` 主体，`pages-*.js` 人物 / 记忆 / 待办页 |

## 开发

```bash
npm test            # 单元测试（node:test）
npm run typecheck   # 类型检查（含测试）
npm run mock-llm    # 启动模拟模型服务（端口 3999，不消耗额度）
```

用模拟模型跑一遍完整流程（创建 → 生成设定 → 连续写作 → 确认提案 → 重写）：

```bash
# 终端 1
npm run mock-llm
# 终端 2（用临时数据目录，避免污染真实作品）
OPENAI_BASE_URL=http://127.0.0.1:3999/v1 OPENAI_API_KEY=mock DATA_DIR=/tmp/novel-dev PORT=3100 npm start
# 终端 3
npm run smoke
```

## 使用建议

- **正文用最好的模型**（决定文笔），`MODEL_FAST` 可以用便宜模型做摘要和记忆抽取；`MODEL_REVIEW` 审校模型默认同 `MODEL`。
- 开启自动审校后每章大约多 1~2 次模型调用；追求速度/省钱时可以关掉，只对重要章节手动审校。
- 前面几层多花时间打磨：世界观和总纲越具体，后面越不容易跑偏。
- 在章节页可以改大纲后「整章重写」，或填要求「按要求修改」。
- 人物的「当前状态」和「伏笔」如果 AI 抽取错了，直接在人物页 / 记忆页改掉。
- 数据在 `data/` 目录，可以直接用编辑器打开，也可以整个目录备份。
